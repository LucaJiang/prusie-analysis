# Benchmark measurement records

All benchmark runtime, memory, iteration, and numerical-agreement records in
this directory were collected on exclusive AMD EPYC 7742 compute nodes using a
single numerical thread.

- `benchmark_records.jsonl.gz`: Full-panel measurement records for all 14,363
  cases (200 GWAS loci, 14,157 eQTL eGenes, and six nested windows), containing
  three retained complete-call and fitting-stage runtimes, per-backend process
  high-water RSS, iteration counts, convergence flags, and numerical comparison
  metrics.
- `benchmark_manuscript_protocol.json`: Summary of manuscript benchmark
  settings, software and wheel SHA256 digests, and runtime/memory measurement
  boundaries.
- `benchmark_primary.tsv`, `benchmark_windows.tsv`, `benchmark_summary.json`:
  Per-case and panel-level summaries generated by
  `04_figures_tables/summarize_benchmark.py`, including medians, quartiles,
  paired speed-up ratios, cumulative runtimes, process peak RSS, case IDs, and
  LD SHA256 digests.
- `ld_class_census.tsv`: Exact signed float64 LD column equivalence class counts
  $G$ across all 200 GWAS loci and 14,157 primary eQTL eGenes (`case_key`,
  `case_id`, `panel`, `p`, `G`, `largest_class`, `variants_in_shared_classes`).
- `ld_class_census_provenance.json`: Provenance metadata for the LD column-class
  census, including panel counts, reference sample sizes, and input table SHA256
  digests.
- `cs_membership.tsv`: Per-case credible-set counts, active component indices,
  and membership agreement derived from the saved final `alpha` matrices of both
  implementations using the `susieR` 0.16.6 credible-set rule (coverage 0.95,
  minimum absolute LD purity 0.5).
- `thread_scaling.tsv`: Multithreaded complete-call runtimes for `prusie` 0.3.0
  at `n_threads` $\in \{2, 4, 8\}$ relative to 1 thread across 182 primary cases
  with $p \ge 1,024$ (exclusive AMD EPYC 7742 nodes, one warmup call and eight
  paired rounds), together with bitwise `alpha` equality checks against the
  single-thread fit.
- `derived_analyses.json`: Per-sweep nested-window runtimes, memory scaling by
  variant count $p$, log-log per-sweep scaling slopes, $G/p$ stratum and tertile
  summaries, and thread-scaling summaries generated by
  `04_figures_tables/derived_analyses.py`.
- `manuscript_numbers.json`: Full-precision summary statistics cited in the
  manuscript text and tables, generated by
  `04_figures_tables/manuscript_numbers.py`.
- `nested_window_audit.json`: Detailed payload verification and summary
  statistics for the six nested variant windows of
  `T2D_chr10_61277948_71054950`.
- `window10000_retime.json`: Ten-call `susieR` replay record for the
  $p = 10,000$ nested window on `cpunode-029`.
- `figure1_traceability.json`, `figure_sources.json`: Input digests and summary
  annotations for the generated figures.
- `primary_case_manifest.tsv`: Genomic coordinates, study and reference sample
  sizes, reference populations, source versions, and input SHA256 digests for
  all 14,357 primary cases.

## Definitions

- **Runtime and speed-up:** Primary speed-up is the ratio of summed per-case
  median runtimes ($\sum \text{median}(T_{\text{susieR}}) /
  \sum \text{median}(T_{\text{prusie}})$) over three retained calls per case and
  backend. The median of per-case ratios and the cumulative ratio across all
  retained calls are reported alongside the primary ratio. Dataset total
  software time is the sum of per-case median runtimes across the panel.
  Complete-call runtime spans a single public `susie_rss` call on preloaded
  input arrays through the returned result.
- **Process peak memory:** `R.peak_rss_diagnostic_bytes` and
  `prusie.peak_rss_diagnostic_bytes` record the process high-water resident set
  size captured immediately after the final timed call (before numerical
  comparison and output serialization) in a fresh worker process that loads the
  inputs and executes one warmup call plus three timed calls. R reads `VmHWM`
  from `/proc/self/status`, and Python reads `ru_maxrss` via
  `resource.getrusage(RUSAGE_SELF)`.
- **Units:** $\text{MiB} = 2^{20}\text{ bytes}$;
  $\text{GiB} = 2^{30}\text{ bytes}$.
