# Benchmark measurement records

Every benchmark timing, memory, iteration and numerical-agreement result reported
in the manuscript comes from measurements on exclusive AMD EPYC 7742 nodes with
one numerical thread.

- `benchmark_records.jsonl.gz`: unchanged full-panel export of all 14,363 cases: 200 GWAS loci, 14,157 eQTL genes and six nested windows. It contains three retained complete-call/fitting-stage times and per-backend process high-water marks, along with numerical, iteration and convergence records.
- `benchmark_manuscript_protocol.json`: manuscript-specific definitions and software identities, with the SHA256 of the archived premeasurement timing protocol. This is a transparent protocol summary, not a replacement frozen original. Reporting existing process peaks is not a newly claimed independent memory campaign.
- `benchmark_primary.tsv`, `benchmark_windows.tsv`, `benchmark_summary.json`: reproducible derivatives, regenerated by `scripts/summarize_benchmark.py`, including medians, quartiles, paired ratios, additive software times, process peaks, case IDs and LD digests.
- `ld_class_census.tsv`: exact signed LD column-class counts G for all 200 GWAS loci and every 20th eQTL gene (708), counted on the locally prepared LD matrices.
- `cs_membership.tsv`: per-case credible sets derived from the saved final alpha of both implementations with the susieR 0.16.6 rule (coverage 0.95, minimum absolute LD purity 0.5), the component indices that form credible sets, and whether membership is identical.
- `thread_scaling.tsv`: prusie 0.3.0 complete-call times with `n_threads` 2, 4 and 8 against one thread for 182 primary-panel cases with p >= 1024 (exclusive AMD EPYC 7742 nodes, one warm-up and eight paired rounds), with bitwise alpha equality to the one-thread fit.
- `derived_analyses.json`: per-sweep nested-window times, memory by region size, per-sweep slopes, G/p comparisons and thread speed-ups, regenerated by `scripts/derived_analyses.py` from `benchmark_primary.tsv`, `benchmark_windows.tsv`, `ld_class_census.tsv` and `thread_scaling.tsv`.
- `nested_window_audit.json`: independent original-payload authentication for all six nested windows, including input/variant/z digests, retained samples, quartiles, iteration counts and recalculated full-precision alpha/PIP differences.
- `figure1_traceability.json`, `figure_sources.json`: figure inputs, definitions and hashes.
- `primary_case_manifest.tsv`: coordinates, sample sizes, reference subsets, source versions and metadata/input digests, without private input paths or genotype data.

## Definitions

Primary speed-up is the ratio of summed per-case median times for susieR and
prusie, using three retained calls per case and implementation. The median of
within-case ratios and the all-call cumulative ratio are separate supplementary
statistics. Dataset total software time sums case medians, counting each analysis
once; it is not the sum of repeats or parallel campaign wall time.
Complete calls accept loaded arrays through returned results, excluding external
preparation, disk reads, imports, explicit garbage collection and serialization.

Main-panel and nested-window memory is `R.peak_rss_diagnostic_bytes` and
`prusie.peak_rss_diagnostic_bytes` in the original records: a full backend-process
high-water mark captured after the last call, before numerical comparison and
serialization. It includes interpreter, libraries, loaded inputs, warmup and
repeated fits. Each backend process runs one warm-up and three timed calls.
These are not independent single-call measurements or fitting-only increments. R uses VmHWM and Python
uses ru_maxrss; the latter may also include pre-exec image residency.

MiB = 2²⁰ bytes; GiB = 2³⁰ bytes.
All cases and retained outliers are included regardless of agreement, convergence
or speed. The files contain measurements and identifiers, not raw association
statistics or individual genotypes.
